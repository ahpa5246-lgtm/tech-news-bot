# Tech News Collector

مكوّن أولي لجمع أخبار التقنية والبرمجيات والبرمجة من مصادر RSS/Atom موثوقة، ثم تنظيفها وتصنيفها وتخزينها محليًا في SQLite. يحافظ المشروع على العنوان والوصف والرابط والتاريخ واللغة الأصلية حتى يمكن تمرير المادة لاحقًا إلى مرحلة كتابة عربية طبيعية.

> لا ينشر هذا الإصدار أي شيء إلى Telegram، ولا يستخدم واجهة ذكاء اصطناعي لإعادة الصياغة أو الترجمة.

## المتطلبات

يحتاج المشروع إلى **Python 3.12 أو أحدث** واتصال بالإنترنت عند تشغيل الجامع. المكتبة الخارجية الوحيدة اللازمة لجلب RSS هي `feedparser`، وتوجد أيضًا `python-dotenv` ضمن المتطلبات تمهيدًا لقراءة ملف البيئة في المراحل التالية.

## التثبيت

من داخل مجلد المشروع:

```bash
python -m venv .venv
```

على Linux وmacOS:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
```

على Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

لا تضع أسرارًا أو رموز وصول في المستودع. ملف `.env` مستثنى من Git، و`.env.example` يحتوي على قيم توضيحية فقط.

## التشغيل

بعد تفعيل البيئة الافتراضية شغّل:

```bash
python main.py
```

ينشئ البرنامج قاعدة البيانات تلقائيًا في `data/news.db`، ثم يفحص المصادر، يستبعد الأخبار الأقدم من 48 ساعة، ويطبع تقريرًا موجزًا بالعناصر الجديدة المخزنة.

## إعداد المصادر

توجد المصادر الفعالة في القاموس `RSS_FEEDS` داخل `config.py`. لإضافة مصدر، أضف زوجًا من الشكل التالي:

```python
RSS_FEEDS["اسم المصدر"] = "https://example.com/feed.xml"
```

يجب استخدام رابط RSS أو Atom مباشر، وليس صفحة HTML عادية. إذا تعطل مصدر، يسجل البرنامج تحذيرًا ويكمل معالجة بقية المصادر دون توقف شامل.

المصادر المبدئية الفعالة هي OpenAI، Google DeepMind، GitHub، Hugging Face، NVIDIA، Microsoft، Apple، TechCrunch، The Verge، Ars Technica، وHacker News. تتغير بنية المواقع بمرور الوقت، ولذلك يتحقق البرنامج من الاستجابة أثناء التشغيل بدل افتراض نجاح كل رابط. تم إبقاء Anthropic معطلًا لعدم توفر رابط RSS رسمي مستقر تم التحقق منه، كما عُطّل Meta AI لأن الرابط المختبر أعاد HTTP 404.

## كيف تعمل المرشحات؟

لا يُرفض الخبر لمجرد أن لغته الإنجليزية. يكتشف `detect_language` وجود مؤشرات عربية أو لاتينية ويخزن القيمة `ar` أو `en` أو `unknown`، مع ترك الترجمة والكتابة العربية لمرحلة لاحقة.

يستخدم مرشح الصلة مجموعة كلمات تقنية في العنوان والوصف، مثل الذكاء الاصطناعي والبرمجة والأمن السيبراني والعتاد والسحابة وقواعد البيانات. كما يستبعد المحتوى العام غير التقني عندما تظهر مؤشرات مثل الرياضة أو أخبار المشاهير دون إشارة تقنية ذات معنى.

يطبق مرشح السلامة ثلاث حالات. فالمحتوى الذي يتضمن ترويجًا مباشرًا لمواد إباحية أو كراهية أو تجنيد إرهابي أو مخدرات غير قانونية أو عنف صادم يُوسم `REJECTED`. أما إذا ظهر مصطلح حساس ضمن سياق بحث أو تقرير أو تحليل أو سلامة، فيُوسم `REVIEW` بدل الحذف التلقائي. هذا تصميم محافظ، لكنه يظل مرشحًا حتميًا بسيطًا وليس بديلًا عن المراجعة البشرية.

درجة الأهمية من 0 إلى 5، وتُرفع عند وجود إشارات تقنية وأفعال مثل إطلاق أو إصدار أو ثغرة أو بحث أو تحديث. لا تُخزن افتراضيًا إلا العناصر التي تبلغ `MIN_IMPORTANCE_SCORE`، وقيمته الافتراضية 3.

## كشف التكرار

يستخدم النظام عدة إشارات متدرجة: إزالة شظايا URL، مطابقة الرابط، و`content_hash` مبني على العنوان والرابط وتاريخ النشر. كما يقارن العناوين الحديثة باستخدام `SequenceMatcher`؛ وإذا تجاوز التشابه 0.88 يعد المقال مكررًا. يحتفظ النظام بالرابط الأصلي والمصدر الأصلي لتسهيل اختيار المصدر الأكثر موثوقية لاحقًا.

## قاعدة البيانات والحالات

جدول `articles` يحوي: `id`، `source`، `title`، `url`، `published_at`، `summary`، `language`، `collected_at`، `content_hash`، `importance_score`، و`status`. الحالات المدعومة هي `NEW` و`ACCEPTED` و`REJECTED` و`REVIEW` و`PUBLISHED`، مع أن النشر غير منفذ حاليًا.

## الإعدادات

يمكن تعديل `MAX_ARTICLE_AGE_HOURS` و`REQUEST_TIMEOUT_SECONDS` و`MIN_IMPORTANCE_SCORE` و`NEWS_DATABASE_PATH` في `.env`. في النسخة الحالية تُقرأ القيم مباشرة من البيئة عند تشغيل البرنامج.

## القيود المعروفة

بعض مواقع الأخبار قد تمنع الطلبات الآلية أو تغير رابط RSS أو تعرض ملخصًا قصيرًا فقط. لا يجلب هذا الإصدار نص المقال الكامل، ولا يتحقق من الحقائق، ولا يحدد المصدر الأكثر سلطوية بين القصص المتشابهة، ولا يستخدم نموذجًا لغويًا لفهم السياق. كما أن اكتشاف اللغة والسلامة والموضوعية قائم على قواعد وكلمات مفتاحية، لذا تُستخدم حالة `REVIEW` عند الغموض.

## ما لم يُنفذ بعد

لم تُنفذ مراحل AI Researcher أو Fact Checker أو Arabic AI Writer أو Human Review UI أو Telegram Publisher أو الجدولة التلقائية أو التصفح المستقل. هذه البنية تفصل الجامع عن تلك المراحل بحيث يمكن إضافتها لاحقًا دون إعادة كتابة طبقة RSS وقاعدة البيانات.

## مخطط التدفق المستقبلي

```text
RSS Collector → News Database → Duplicate Detector → Relevance Classifier
→ AI Researcher → Fact Checker → Arabic AI Writer → Human Review → Telegram Publisher
```


## Phase 2 — AI News Analyst

أضيفت طبقة **AI News Analyst** فوق جامع RSS ومرشحات Phase 1 دون استبدالها. أصبح التدفق:

```text
RSS Sources
    ↓
Phase 1 Collector
    ↓
Phase 1 Filters and Duplicate Detection
    ↓
SQLite
    ↓
Phase 2 AI News Analyst
    ↓
Structured Editorial Decision
    ↓
SQLite
```

يستقبل المحلل الحقول الموجودة أصلًا: العنوان، المصدر، الرابط، تاريخ النشر، الملخص، اللغة، درجة Phase 1، والحالة. ويعيد JSON منظمًا يتضمن القرار `ACCEPT` أو `REVIEW` أو `REJECT`، الثقة، الفئة، درجة أهمية تحريرية، ملخصًا عربيًا تحليليًا، ما حدث، لماذا يهم، الحقائق الأساسية، الادعاءات وحالة التحقق، حالة السلامة، الحاجة إلى المراجعة أو البحث، وسبب الرفض عند الحاجة.

لا ينتج المحلل منشور Telegram نهائيًا. حقلا `summary_ar` و`what_happened` و`why_it_matters` هما تحليل عربي داخلي دقيق، وسيستخدمهما **Phase 3 — Arabic AI Writer** لاحقًا لصناعة المنشور الطبيعي.

### مزود الذكاء الاصطناعي

يستخدم المشروع واجهة مزود عامة في `ai/base.py`، مع تنفيذ OpenAI-compatible اختياري في `ai/provider.py`. لا يعتمد التشغيل الأساسي على الذكاء الاصطناعي، ويمكن تشغيل Phase 1 بدون أي مفتاح أو اعتماد.

ضع القيم التالية في `.env` عند تفعيل المزود:

```text
AI_PROVIDER=openai_compatible
AI_MODEL=gpt-5-mini
AI_API_KEY=ضع_المفتاح_هنا
AI_API_BASE=https://your-provider.example/v1
AI_TIMEOUT_SECONDS=45
```

يمكن استخدام أي نقطة نهاية متوافقة مع Chat Completions وJSON Schema. في بيئة Manus يمكن استخدام نقطة النهاية المتاحة في متغيرات البيئة المناسبة، لكن لا تضع المفتاح في Git. إذا بقي `AI_PROVIDER` فارغًا، يطبع البرنامج تحذيرًا واضحًا ويستمر دون تحليل.

### أوامر التشغيل

يبقى الأمر القديم متوافقًا:

```bash
python main.py
```

ويشغّل جامع Phase 1 فقط. لتشغيل التحليل على المقالات التي حالتها `NEW` أو `ACCEPTED` أو `REVIEW` ولم تُحلل بنجاح:

```bash
python main.py --analyze
```

لتحديد عدد المقالات:

```bash
python main.py --analyze --limit 10
```

ولإعادة تحليل المقالات التي تحمل حالة `ANALYZED` عمدًا:

```bash
python main.py --analyze --reanalyze
```

### قاعدة البيانات وحالة التحليل

أُضيفت أعمدة Phase 2 إلى جدول `articles` بإضافة migration آمنة لا تحذف البيانات أو تعيد إنشاء قاعدة قديمة. أهم الحقول هي `ai_decision`، `ai_confidence`، `ai_category`، `ai_summary_ar`، `ai_what_happened`، `ai_why_it_matters`، `ai_key_facts`، `ai_claims`، `ai_safety_status`، `ai_needs_research`، `ai_analyzed_at`، `ai_model`، و`ai_error`.

حالة التحليل هي `NOT_ANALYZED` أو `ANALYZING` أو `ANALYZED` أو `AI_ERROR`. لا يعاد تحليل المقال الناجح تلقائيًا، بينما يمكن طلب ذلك صراحة باستخدام `--reanalyze`. إذا فشل المزود أو أعاد JSON غير صالح، تحفظ الحالة `AI_ERROR` ويستمر البرنامج مع المقالات الأخرى.

### السلامة والتحقق ومنع الهلوسة

يفصل المحلل بين الترويج لمحتوى ضار وبين التقرير المشروع عنه. لذلك قد تكون تقارير الأمن السيبراني أو أبحاث خطاب الكراهية أو الشبكات المتطرفة مؤهلة للمراجعة بدل الرفض الآلي. كما أن وجود ادعاء في ملخص RSS لا يجعله متحققًا تلقائيًا؛ تستخدم الادعاءات حالات `SUPPORTED` أو `UNSUPPORTED` أو `UNCERTAIN` أو `NOT_CHECKED`، ويُطلب `needs_research=true` عند الحاجة إلى مصدر مستقل.

يُتحقق من بنية JSON برمجيًا قبل تخزينه، ولا يستخدم المشروع `eval()` أو قبولًا صامتًا لحقول ناقصة. إذا لم يكن لدى النظام بحث مستقل، تبقى خطوة البحث خارجية ويحدد المحلل الحاجة إليها بدل اختلاق دليل.

### الاختبارات المنفذة

تشمل اختبارات Phase 2 التحقق من JSON الصحيح، الحقول الناقصة والقرار أو الدرجة غير الصالحة، التمييز بين التقرير الأمني الحساس والمحتوى الضار، حساب الأهمية، migration قاعدة Phase 1 مع الحفاظ على المقالات، تخزين تحليل مزود وهمي صالح، والتعامل مع استجابة مزود غير صالحة دون إسقاط البرنامج.

### ما يزال غير منفذ

لم تُنفذ كتابة منشور Telegram النهائي، أو النشر إلى Telegram، أو الجدولة، أو التصفح المستقل، أو الباحث الآلي، أو التحقق الخارجي من الحقائق، أو لوحة المراجعة البشرية، أو الصور والفيديو والصوت، أو تعدد الوكلاء. المرحلة التالية المخططة هي **Phase 3 — Arabic AI Writer** لتحويل القرار التحريري المقبول إلى منشور عربي طبيعي ودقيق.


## Phase 3 — News Source Research & Verification

أضيفت مرحلة بحث المصدر الأصلي فوق جامع RSS ومحلل Phase 2. لا تكتب هذه المرحلة منشور Telegram ولا تترجم المقال؛ وظيفتها استرجاع صفحة المصدر الأصلية عند الإمكان، استخراج محتواها الرئيسي، مقارنة بيانات RSS بالصفحة، وتخزين نتيجة بحث منظمة يمكن أن يستهلكها الكاتب العربي في Phase 4.

### الأمر الجديد

```bash
python main.py --research
python main.py --research --limit 10
python main.py --research --reresearch
```

يبحث الأمر في المقالات ذات الحالات `ACCEPTED` و`REVIEW` التي لم تُبحث بنجاح. لا يعيد البحث في المقالات ذات الحالة `VERIFIED` إلا عند استخدام `--reresearch`. ويبقى الأمران السابقان متاحين دون تغيير:

```bash
python main.py
python main.py --analyze
```

### جلب المصدر واستخراج المحتوى

تستخدم طبقة `research/source.py` طلبات HTTP عادية بمهلة زمنية وUser-Agent واضح، وتتبع التحويلات التي ينفذها الخادم تلقائيًا، وتسجل أخطاء HTTP والاتصال والمهلة والروابط غير الصالحة. لا تحاول تجاوز تسجيل الدخول أو الجدران المدفوعة أو CAPTCHA أو قيود الوصول، ولا تستخدم إعادة محاولات عدوانية. يحدد الجلب حدًا أقصى لحجم الصفحة ويكمل بقية المقالات إذا فشل مصدر واحد.

تُحلل الصفحة عبر BeautifulSoup، مع إزالة السكربتات والقوائم والتذييل والنماذج والإطارات والعناصر غير المناسبة، ثم اختيار `article` أو `main` أو `body` واستخراج الفقرات والعناوين ذات المحتوى الكافي. تُحفظ أيضًا بيانات العنوان والمؤلف والتاريخ واسم الموقع والرابط canonical والنطاق. إذا كان النص قصيرًا أو فارغًا، تُسجل النتيجة للمراجعة بدل اعتبارها مصدرًا موثوقًا.

### التحقق

إذا توفر مزود Phase 2، يعاد استخدامه عبر دالة مستقلة `verify_source` مع تلقينة ومخطط JSON منفصلين. يقارن المدقق عنوان RSS بعنوان الصفحة، ويصنف النتيجة إلى `VERIFIED` أو `REVIEW` أو `RESEARCH_ERROR`. حالات الادعاءات الداخلية هي `SUPPORTED` أو `PARTIALLY_SUPPORTED` أو `UNSUPPORTED` أو `UNABLE_TO_VERIFY` داخل المعلومات التي يقدمها المصدر؛ ولا يسمح النظام باختلاق أدلة أو تواريخ أو مواصفات أو اقتباسات.

عند غياب مزود الذكاء الاصطناعي، لا تتوقف Phase 3. تُحفظ بيانات الاسترجاع والاستخراج، ويستخدم النظام تحققًا حتميًا محافظًا يعتمد على نجاح الاستخراج وتشابه العنوان. هذا لا يدعي تحقق كل الحقائق؛ بل يوضح أن المصدر استُرجع، ويترك الادعاءات التفصيلية للمراجعة أو التحقق اللاحق.

### قاعدة البيانات

أضيفت Migration additive إلى جدول `articles` دون حذف مقالات Phase 1 أو تحليلات Phase 2. الحقول الجديدة تشمل `research_status`، `researched_at`، `source_accessible`، `source_http_status`، `source_url`، `source_domain`، `source_name`، `canonical_url`، `extracted_title`، `extracted_author`، `extracted_publication_date`، `extracted_content`، `verification_status`، `verified_claims`، `unsupported_claims`، `verification_summary`، `safety_flags`، `verification_confidence`، و`research_error`.

الحالات الأساسية هي `RESEARCH_PENDING` و`RESEARCHING` و`VERIFIED` و`REVIEW` و`RESEARCH_ERROR`. لا تُحذف المقالات عند فشل الموقع، بل تحفظ حالة الخطأ ومعلوماته. وتبقى بيانات Phase 2 مثل `ai_decision` و`ai_summary_ar` محفوظة كما هي.

### السلامة

لا تحول هذه المرحلة أخبار الأمن السيبراني إلى إرشادات تشغيلية ضارة. النص المصدر يُخزن للبحث التحريري، لكن النظام لا يولد خطوات استغلال أو نشر برمجيات خبيثة أو سرقة بيانات اعتماد أو تجاوز ضوابط. كما أن التقارير المشروعة عن الجرائم أو الحروب أو الأمن أو التقنيات الحساسة لا تُرفض تلقائيًا؛ عند الغموض تُستخدم `REVIEW`.

### الاختبارات

تتضمن اختبارات Phase 3 جلبًا ناجحًا وهميًا، HTTP 404، المهلة، الرابط غير الصالح، استخراج النص، الرابط canonical، المؤلف، المقال الفارغ، عدم تطابق العنوان، تحقق JSON، Migration من قاعدة Phase 2، الحفاظ على تحليل Phase 2، البحث بدون AI، والبحث مع مزود AI وهمي. لا تعتمد الاختبارات على مواقع حية.

### الاعتماديات والإعداد

أضيفت `beautifulsoup4` فقط لأنها مطلوبة لاستخراج المحتوى الرئيسي من HTML بشكل متسامح مع اختلاف تخطيطات المواقع. حدّث البيئة بعد تنزيل المشروع:

```bash
python -m pip install -r requirements.txt
```

لا توجد متغيرات سرية جديدة مطلوبة لـ Phase 3؛ تستخدم إعدادات HTTP الموجودة. وإذا أردت التحقق عبر AI، تستخدم إعدادات Phase 2 الموجودة في `.env`، دون حفظ أي مفتاح داخل المشروع.

### الحدود الحالية

لا تتطلب Phase 3 مصدرين مستقلين، ولا تنفذ بحثًا عامًا عبر محركات البحث، ولا تتحقق من كل ادعاء رقمي بمراجع خارجية، ولا تتجاوز الجدران المدفوعة أو CAPTCHA، ولا تنفذ نشرًا آليًا. المرحلة التالية هي **Phase 4 — Arabic AI Writer** التي ستستخدم التحليل والبحث الموثقين لإنتاج نص عربي طبيعي، ولن تُنفذ في هذه المرحلة.
